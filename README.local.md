# CRBU 로컬 실행

저장소 루트에서 실행합니다.

## 실행

```powershell
npm install
npm run dev
```

브라우저 주소: http://127.0.0.1:5173/

`.env.local`에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 설정합니다. 환경 파일은 Git에서 제외됩니다. 서버 전용 키는 브라우저 코드나 `VITE_` 변수에 넣지 않습니다.

## 화면과 데이터

GitHub `main`의 모바일 전용 화면 구성과 T03 오픈·마감 체크리스트 UI를 사용합니다. 별도의 대체 UI/CSS는 사용하지 않습니다. 표시값과 이벤트를 `src/live.tsx`, `src/api.ts`를 통해 실제 데이터에 연결했습니다.

- 원본 매장명, 온도 기준, 일일 업무, 매출, 폐기, 점검 지적사항을 조회합니다.
- 점검 완료 여부는 클릭 즉시 반영하고 뒤에서 저장합니다. 빠른 반복 클릭은 항목별로 순서대로 처리하며 저장 실패 시 이전 저장값으로 복구합니다.
- 오픈·마감 화면은 실제 업무 템플릿과 측정 기준을 표시합니다. 측정값은 입력칸을 벗어나면 저장하며, 오픈과 마감은 각각 별도 화면에서 확인합니다. 비정상 점검 결과도 저장됩니다.
- SV 보고서에는 가져온 주간 보고서와 새로 제출한 보고서가 함께 표시됩니다. 가져온 보고서는 원본을 유지하며 조회만 제공합니다. 직접 제출한 보고서와 이슈는 내역에서 수정하고, 삭제 시 복구 가능한 상태로 보관합니다.
- 달력은 원본 데이터 기간 밖의 날짜도 선택할 수 있습니다. 기록이 없는 날은 실제 업무 템플릿으로 빈 점검표를 표시합니다.
- 비용, 보고서, 측정값, 발주 초안, 이슈 조치와 SV 확인을 별도의 `runn_` 테이블에 저장합니다. 가져온 `t1_`/`t2_` 데이터는 변경하지 않습니다.
- 실제 데이터에 없는 리뷰와 AI 분석은 준비 중으로 표시합니다. AI API는 연결하지 않았습니다.

## 계정과 권한

최초 접속 시 로그인 화면을 표시합니다. 회원가입에서 아이디·비밀번호·역할을 입력하며, 점장은 담당 매장을 선택합니다. 가입 완료 후 로그인하면 저장된 역할에 따라 점장 또는 SV 화면이 열립니다. 역할 전환 버튼은 로그아웃으로 변경했습니다.

계정은 Supabase Auth의 `auth.users`에 저장합니다. 비밀번호는 Auth가 관리하며 앱 테이블에 평문으로 저장하지 않습니다. 사용자명과 역할·매장은 서버에서 설정하는 `app_metadata`에 저장하고, API 요청마다 Auth가 확인한 사용자 정보로 권한을 적용합니다. 사용자가 수정할 수 있는 `user_metadata`는 권한 판단에 사용하지 않습니다. 별도 SQL 마이그레이션은 필요하지 않습니다.

이메일 입력 없이 아이디로 가입하므로 서버에서 정규화한 아이디를 해시한 내부 이메일 식별자를 사용합니다. 이메일 발송·인증·비밀번호 재설정 메일은 제공하지 않습니다. 같은 아이디는 영문 대소문자를 구분하지 않습니다. 비밀번호는 8~128자입니다. 액세스·리프레시 토큰은 HttpOnly 쿠키로 보관하며 Vercel에서는 Secure를 적용합니다. 세션이 만료되면 갱신하고, 로그아웃 시 갱신 세션을 종료하고 쿠키를 제거합니다.

요청대로 가입 시 점장/SV를 직접 선택할 수 있습니다. 점장은 가입한 매장의 데이터만 조회·수정하며, SV는 전체 매장을 확인합니다. 가입 시 역할과 매장을 지정한 후 화면이나 `/api/session` 요청으로 임의 변경할 수 없습니다. 가입·로그인 추가 시도 제한은 프로세스 단위이며 Supabase의 로그인 제한도 적용됩니다.

로컬 서버는 루프백에서 실행하며 같은 API가 Vercel 서버리스 엔트리에서도 동작합니다. 기존 Vercel 서버 환경변수 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 사용합니다. GitHub main에 반영하면 기존 Vercel 연동으로 온라인에 배포합니다. 발주는 초안만 저장하며 공급업체에 전송하지 않습니다. AI API는 연결하지 않습니다.

## 검증

```powershell
npm run typecheck
npm run build
npm test
node --env-file=.env.local tests/integration.mjs
```

통합 검증은 실행 중인 로컬 서버와 실제 데이터베이스를 사용합니다. 검증에서 만든 계정과 행만 정리하고 기존 원본 기록은 보존합니다. `npm run build` 산출물만 정적 호스팅하면 API가 없으므로 조회·저장이 동작하지 않습니다. 저장소의 `api/[...path].ts`와 `vercel.json`은 서버 API 배포 구성을 제공합니다.

온라인 주소: https://crycheese-one.vercel.app/

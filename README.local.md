# RUNN 로컬 검토

저장소 루트에서 실행합니다.

## 실행

```powershell
npm install
npm run dev
```

브라우저 주소: http://127.0.0.1:5173/

`.env.local`에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 설정합니다. 환경 파일은 Git에서 제외됩니다. 서버 전용 키는 브라우저 코드나 `VITE_` 변수에 넣지 않습니다.

## 화면과 데이터

GitHub `main`의 화면 구성과 오픈·마감 체크리스트 UI를 사용합니다. 별도의 대체 UI/CSS는 사용하지 않습니다. 표시값과 이벤트를 `src/live.tsx`, `src/api.ts`를 통해 실제 데이터에 연결했습니다.

- 원본 매장명, 온도 기준, 일일 업무, 매출, 폐기, 점검 지적사항을 조회합니다.
- 점검 완료 여부는 클릭 즉시 반영하고 뒤에서 저장합니다. 빠른 반복 클릭은 항목별로 순서대로 처리하며 저장 실패 시 이전 저장값으로 복구합니다.
- 오픈·마감 화면은 실제 업무 템플릿과 측정 기준을 표시합니다. 측정값은 입력칸을 벗어나면 저장하며, 오픈 측정값이 저장되고 점검을 모두 확인하면 마감 항목이 열립니다. 비정상 점검 결과도 저장됩니다.
- SV 보고서에는 가져온 주간 보고서와 새로 제출한 보고서가 함께 표시됩니다. 가져온 보고서는 원본을 유지하며 조회만 제공합니다.
- 달력은 원본 데이터 기간 밖의 날짜도 선택할 수 있습니다. 기록이 없는 날은 실제 업무 템플릿으로 빈 점검표를 표시합니다.
- 비용, 보고서, 측정값, 발주 초안, 이슈 조치와 SV 확인을 별도의 `runn_` 테이블에 저장합니다. 가져온 `t1_`/`t2_` 데이터는 변경하지 않습니다.
- 실제 데이터에 없는 리뷰와 AI 분석은 준비 중으로 표시합니다. AI API는 연결하지 않았습니다.

## 검토 범위

이 서버는 이 컴퓨터의 루프백 주소에서 검토하는 프로토타입입니다. 점장/SV 버튼은 검토용 역할 전환이며 운영용 직원 인증이 아닙니다. 발주는 초안만 저장하고 공급업체에 전송하지 않습니다. 사용자 계정·알림·리뷰·사진 첨부 기능은 후속 구현 대상입니다.

## 검증

```powershell
npm run typecheck
npm run build
npm test
node --env-file=.env.local tests/integration.mjs
```

통합 검증은 실행 중인 로컬 서버와 실제 데이터베이스를 사용합니다. 검증에서 만든 행만 정리하고 기존 원본 기록은 보존합니다. `npm run build` 산출물만 정적 호스팅하면 API가 없으므로 조회·저장이 동작하지 않습니다. 운영 배포 전에는 서버 API와 직원 인증 구성이 필요합니다.

PR은 로컬 검토용 구현을 공유합니다. 운영 배포와 병합은 별도로 진행합니다.
